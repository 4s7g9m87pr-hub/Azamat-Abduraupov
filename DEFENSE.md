«Я сделал адаптивный сайт-портфолио UI/UX-дизайнера. На сайте есть меню, главный экран, четыре учебных кейса, информация обо мне, цены и форма. В этой учебной версии бриф сохраняется в браузере, его можно скачать или удалить».

## Короткий вариант на английском

My project is a UI/UX designer portfolio website. It has a header, a hero section, project cards, prices, a contact form, and a footer. I used HTML, CSS, and JavaScript. The website works on computers and phones. On a phone, the menu becomes a burger menu. The project cards use CSS Grid. There are light and dark themes. The form checks the name, email, phone, and project link. This is a student demo, so the brief is saved in the browser. It is not sent by email.

## Вопросы и простые ответы

**1. Что такое Mobile First?**  
Сначала я пишу стили для телефона. Потом через `@media` добавляю изменения для больших экранов. Так базовая версия сразу подходит узкому экрану.

**2. Где в проекте Mobile First?**  
В начале `style.css` сетка hero содержит 4 колонки, карточки идут в одну колонку, а навигация скрыта. В `@media (min-width: 1024px)` hero получает 12 колонок и появляется горизонтальное меню.

**3. Что такое CSS Grid?**  
Это способ расположить элементы по строкам и колонкам. Например, `.project-grid` показывает карточки проектов. На телефоне одна колонка, на большом экране две.

**4. Для чего Flexbox?**  
Он помогает расположить элементы в одном направлении. В проекте он используется для меню, кнопок, тегов и нижнего блока.

**5. Для чего семантические теги?**  
Они объясняют назначение частей страницы браузеру, поисковику и программам чтения с экрана. `nav` — навигация, `main` — основное содержимое, `article` — отдельная карточка.

**6. Почему rem и проценты?**  
`rem` зависит от базового размера шрифта, а проценты — от размера контейнера. Вместе с Grid это помогает странице адаптироваться. В `style.css` нет фиксированной геометрии контентных блоков в px. Px используется только в требуемом условии media query.

**7. Как проверяется форма?**  
`required` запрещает пустое обязательное поле. `type="email"` проверяет формат email. `type="url"` проверяет ссылку. Для телефона используются `type="tel"` и `pattern`, потому что tel сам по себе не проверяет формат номера. CSS `:user-invalid` меняет рамку поля после некорректного ввода.

**8. Куда отправляется форма?**  
В этой версии никуда. После согласия один бриф сохраняется в localStorage этого браузера. Можно скачать текстовую копию или удалить её. Для настоящего приёма заявок нужен backend или согласованный сервис формы.

**9. Как работает тёмная тема?**  
Кнопка меняет атрибут `data-theme` у `html`. CSS-переменные задают другой фон, текст, границы и акценты. Выбор хранится в localStorage. Если выбора нет, сайт учитывает системную тему.

**10. Что такое Git?**  
Это система контроля версий. Она сохраняет изменения проекта в коммитах. Можно понять, что изменилось, сравнить версии и вернуться к предыдущей.

**11. Что такое коммит?**  
Это сохранённый шаг разработки. Например, сначала структура HTML, потом адаптивные стили, затем интерактивность. `feat:` означает новую возможность, `fix:` — исправление, `docs:` — документацию.

**12. Чем Git отличается от GitHub?**  
Git хранит историю версий. GitHub — сервис, где можно разместить Git-репозиторий и работать с ним через интернет.

**13. Что такое GitHub Pages?**  
Это хостинг статических HTML/CSS/JS-файлов из репозитория. Он не выполняет серверный обработчик формы, поэтому сам по себе не отправляет письма.

**14. Почему SVG и WebP?**  
SVG хранит векторные фигуры и подходит для масштабирования и импорта в Figma. В экспортированных иллюстрациях текст переведён в контуры. WebP — растровый формат, удобный для компактных изображений.

**15. Что такое Thumb Zone?**  
Это область экрана, до которой удобно дотянуться большим пальцем. На телефоне внизу есть заметная кнопка контакта. Основные кнопки имеют достаточно большую область нажатия.

**16. Какие проверки доступности есть?**  
Подписи полей, alt у изображений, видимый фокус, skip-link, навигация клавиатурой, aria-expanded у меню, role=switch у темы, диалоги с закрытием по Escape и reduced motion.

## Что показать преподавателю по порядку

1. Открыть сайт и перейти по кнопке View cases.
2. Открыть один кейс и закрыть его кнопкой или Escape.
3. Показать меню и карточки в макете шириной 390.
4. Включить тёмную тему.
5. Нажать Save project brief с пустыми полями и показать проверку.
6. Заполнить тестовыми данными, сохранить, скачать бриф и удалить его.
7. Открыть код и показать семантические теги, Grid и media query.
8. Показать историю Git и публичный GitHub Pages, если публикация завершена.
9. Показать четыре нативных frame в Figma после импорта и проверки.
